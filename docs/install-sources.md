# Where the launcher downloads from

- App releases come from `https://github.com/storytold/<app>/releases` and GitHub's asset CDN. An approved community app comes from its own repository, pinned in the catalog (`CraftApp::repo`, `AppKind::Community`): today `https://github.com/tangency-labs/solidcraft/releases` (SolidCraft) and `https://github.com/UCSLabs/mailcraft/releases` (MailCraft). The release feed can move an app within `storytold/`, not to another owner. A catalog entry's `former_repo` (MailCraft's `UCS-Care-Group/mailcraft`, until that name stops redirecting) is accepted when the release feed still names it, and its downloads must then be under `former_repo`.
- Which release is current, and every app's version history, come only from ArtCraft's release service (`https://api.storyteller.ai/v1/craft_apps/release_info` and `…/{app}/releases`). The launcher never asks GitHub's API; when the service can't be reached, it says it couldn't check.
- A developer's own loopback mirror (`ARTCRAFT_LAUNCHER_DOWNLOAD_BASE`, `cargo xtask local`) is read only by builds with the `local-mirror` cargo feature, which release builds do not enable, and only for loopback addresses.
  - In a debug build with that feature, the Developer Builds (Nightly) track uses the same base as a one-app test transport for PhotoCraft (`crates/native/src/http.rs`, `NightlyMirror`). It maps PhotoCraft's release history (`https://api.storyteller.ai/v1/craft_apps/photocraft/releases`) to `<base>nightly/photocraft/releases.json`, and each `https://github.com/storytold/photocraft/releases/download/<tag>/<file>` to `<base>nightly/photocraft/assets/<tag>/<file>`. It refuses every other address. `releases.json` must use the release service's history format, not GitHub's release list: `{"repo": "storytold/photocraft", "app_last_fetched": "<RFC 3339 time>", "complete": true, "releases": [{"tag", "name", "published_at", "html_url", "prerelease", "notes_markdown", "assets": [{"name", "size_bytes", "download_url", "sha256"}]}]}`, newest first. Each `download_url` must be the logical GitHub download address above, not the loopback one. `app_last_fetched` must be less than a day old (`feed::MAX_AGE`), so refresh it before each run, or the history is treated as unknown. Each nightly's `SHA256SUMS.txt` and `NIGHTLY.json` go under `assets/<tag>/`, as before.
- Each download is verified against the release's `SHA256SUMS.txt` before it is run or installed, community apps included. On macOS the launcher also requires the Developer ID signature of the app's own team (`CraftApp::mac_team`: ArtCraft's for official apps, SolidCraft's for SolidCraft). An app with `mac_team = None` (today MailCraft) is not installed there, only opened if present.
- The details drawer's pictures are JPEGs from a pinned tag of `https://raw.githubusercontent.com/storytold/craft-launcher-assets/` (`core::details`). Each is capped at 2 MB, cached and never run. They are not bundled in this repository.
- Requests send the User-Agent `ArtCraft-Launcher/<version>` and no personal details.
