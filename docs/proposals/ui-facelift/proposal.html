What stays untouched

  • crates/core, crates/native, both app shells, packaging.
  • LauncherUi::logic, handle, the Command / Event protocol and the settings file.
  • Every button still sends the same command it sends today; only where it is drawn changes.
  • AGENTS.md "Look and feel": the theme::Tokens colours, Archivo, Inter and Geist Mono, square corners and 1 px hairlines. The mockup only uses them more boldly: inverted blocks for the active filter and the update band, a large Archivo heading, and an app-colour tint with corner marks on hover. Motion still follows reduce_motion.
  • CI workflows. Each step is an ordinary PR.

Costs and risks

  • New dependencies need a maintainer's yes. Both releases are under three weeks old: pin exact versions, check licences for ATTRIBUTION.md, and check the wasm32 build and its size.
  • Translations. Reuse existing strings (All, Installed, Updates, Not installed, Pinned, Update all, Search apps). A new one such as "2 updates ready" needs a row in all 12 catalogs.
  • UI tests. tests/ui.rs (3,338 lines) will need updates wherever it finds widgets by position or by the toolbar.
  • Taffy in egui lays out from sizes it measured earlier, so a resize may take an extra frame to settle. Worth measuring early.
  • Fallback. If egui_taffy isn't approved, phase 3 can use variable row heights in the existing hand-built grid.

Delivery plan

One PR per step, each shippable on its own
  1. 1

    Groundwork, no visual change

    Add a spacing scale to the theme (4, 8, 12, 16, 24, 32) and replace the loose numbers. Add screenshot tests with egui_kittest so the next steps show their exact visual diff.

    theme.rs · views.rs · tests/
  2. 2

    New frame

    Side rail with filters, pinned apps and the old footer content; search moves to the header; filter chips when narrow.

    app.rs ui() · views.rs header, toolbar, footer
  3. 3

    Card grid

    egui_taffy grid with auto-fill columns and rows sized to their content; the Pinned, Installed and Not installed groups stay as they are.

    views.rs grid, grid_block · Cargo.toml
  4. 4

    Cards, rows and update band

    Drop the number strip, move links into the menu, tiles for installed apps and slim rows for the rest, update band above the grid.

    views.rs card · card_parts.rs · i18n catalogs if a string is added
  5. 5

    Dock and details drawer

    The launcher dock of installed apps on top, and the details as a tabbed drawer from the right, coloured per app.

    views.rs · details.rs

Decisions needed

2. May ui-egui take egui_flex and egui_taffy as dependencies?

4. Can the footer go, with its content in the rail?

5. Should app details open as a tabbed drawer from the right instead of today's centred page?
